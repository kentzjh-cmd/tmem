# 研究课题：记忆载体消融与量化——tmem 结构化记忆 vs 散文式 MD 记忆 vs 无记忆

> **状态**：`待执行（已立项）` ｜ **立项日期**：2026-11-22 ｜ **立项依据**：[`docs/dsh-independent-e2e-report.md`](./dsh-independent-e2e-report.md) §3.6 / §5.1 / §5.3
> **研究类型**：受控消融实验（因子设计 + 内容等价控制 + 预注册门槛 + 重复采样 + 机器可读判定 + 定性行为编码）
> **一句话课题**：**在知识内容完全相同的前提下，"以什么载体承载工程记忆、agent 以什么方式获取它"，对任务效果与 token 成本分别有多大影响？**
> **三个因子**：载体（tmem 结构化 / 散文式 MD）× 获取方式（自动注入 / 按需读取）× **上下文压缩（压缩 / 不压缩）**
> **三个指标族**：成本（token / 上下文占用 / 折算费用）× 效果（复发率 / 采纳率 / 完成率）× 结构化独有（共变拓扑 / 错误签名→修复对）
> **定性与定量并重**：压缩专项除定量指标外，配一套**可双人独立编码的行为编码表**（Q1–Q7，含 Cohen's κ 校准），两类结论必须交叉验证

---

## 0. 为什么要立这个课题

上一轮独立 E2E 研究（11 场真实会话、9 条门槛）得到三个直接催生本课题的结论：

1. **"记忆内容"和"记忆载体"被混在一起测了。** 三臂对照中 A（tmem）与 B（散文式 `AGENTS.md`）召回率完全相同（A−B = 0.00），因为 agent **自己**会把约定写进 `README.md`/`AGENTS.md`，从而**完全遮蔽**了插件的贡献。要测出 tmem 的价值，必须把载体与内容分离。
2. **B 臂不是纯无插件基线。** 全局 `tmem` CLI 仍在 `PATH` 上且被 agent 主动调用，B 臂实际测到的是"**无自动注入**"，不是"无 tmem"。这让"插件独占能力"的边界至今没有被干净地划出。
3. **G7 的探针不具备记忆专有性**（答案分别来自提示词、fixture 初始代码、代码常量），导致"插件边际贡献"这一最关键的问题**测不出来**（详见报告 §3.6 的事后更正）。

**因此本课题不是"再跑一遍效果验证"，而是补上上一轮缺失的那一格：把载体效应从内容效应里剥出来，并把它换算成可比较的量（token、成本、复发率）。**

## 1. 研究问题与可证伪假设

| 编号 | 假设（可证伪陈述） | 若为真，则应观察到 |
| :--- | :--- | :--- |
| **H-A** | **成本优势**：tmem 的定向注入以显著更少的 token 取得同等知识量 | tmem 臂的"知识获取 token"显著低于 MD 臂（阈值见 §6） |
| **H-B** | **效果优势**：结构化记忆降低同类问题的**复发** | tmem 臂的"同签名复发率"显著低于 MD 臂与无记忆臂 |
| **H-C** | **结构化独有**：共变拓扑与"错误签名→修复对"是散文载体无法表达的信息 | tmem 臂的 L1 提示采纳精确率显著高于 MD 臂（后者恒为 0） |
| **H-D** | **获取方式效应可分离**：定向注入优于全量注入，即使载体相同 | 同载体下，"自动注入"臂的知识获取 token 低于"按需读取"臂，且效果不劣 |

> H-D 是本课题的**核心因子检验**：若 tmem 的优势只来自"自动"而非"结构化"，H-D 成立而 H-A 只在自动臂成立；若结构化也重要，则两个因子各自贡献可分离。

**第三因子：上下文压缩（compaction）**（见 §4）。上下文被压缩后，模型live context 里的历史信息会丢失；此时"记忆能否被找回来、以什么代价找回"，是本课题不可回避的一维。

| 编号 | 假设（可证伪陈述） | 若为真，则应观察到 |
| :--- | :--- | :--- |
| **H-E** | **压缩后回收**：tmem 的压缩归档（episode + 倒排索引 + `<tmem_compacted_index>` 通知）能在压缩后以更少 token 找回被丢弃的关键知识，优于依赖 harness 原生摘要 | 压缩+tmem 臂的"知识找回 token" ≤ 压缩+无 tmem 臂，且效果不劣 |
| **H-F** | **重注入缺口可修复**：压缩后 tmem 应当**重新注入**此前注入过的历史修复（当前实现中 `injected_trace_ids` 只增不删，压缩后不会重注入） | 修复后压缩后重注入率由 0 提升到 ≥ 阈值，且压缩后复发率下降 |

## 2. 因子设计与实验臂

**两个正交因子**（载体 × 获取方式）+ 一个基线臂；**第三因子（压缩）**见 §2.0b 与 §3.4：

| 臂 | 载体 | 获取方式 | 说明 |
| :--- | :--- | :--- | :--- |
| **A1** | tmem 结构化 | **自动注入**（hook 定向注入匹配片段） | 现状 |
| **A2** | tmem 结构化 | 按需读取（agent 主动 `tmem lookup`） | 分离"结构化"与"自动" |
| **B1** | 散文式 MD | **全量注入**（把 MD 全文注入上下文） | 分离"结构化"与"自动" |
| **B2** | 散文式 MD | 按需读取（agent 主动 `read` MD 文件） | 最常见的现状做法 |
| **C** | 无记忆 | — | 基线 |

> **载体**：tmem = `.tmem/` 结构化存储（trace/episode/错误签名/共变拓扑/L0 路径）；散文式 MD = `AGENTS.md` + `README.md` 的人写散文。
> **获取方式**：自动注入 = 无需 agent 主动动作即进入上下文；按需读取 = agent 自主发起工具调用才进入上下文。

### 2.0b 第三因子：压缩

在 §2 的 5 臂之上追加**第三因子 `压缩 ∈ {不压缩, 中途强制压缩}`**。压缩专项用下列 4 个对照臂（其余因子固定为"载体=tmem 结构化 + 获取方式=自动注入"，以便看清压缩效应）：

| 臂 | 压缩 | tmem | 作用 |
| :--- | :--- | :--- | :--- |
| **C1** | 否 | 是 | 不压缩基线：给出"知识成本与效果"的正常水位 |
| **C2** | 是 | 是 | **主实验**：压缩后靠 tmem 找回知识 |
| **C3** | 是 | 否 | **关键对照**：harness 原生摘要本身能不能保住信息？**不设 C3 会系统性高估 tmem** |
| **C4** | 是 | 是（**关闭重注入**） | 消融：量化"重注入缺口"造成的损失（当前实现即此状态） |

> **C4 的必要性**：`tmem/hooks/dsh.mjs` 中 `state.injected_trace_ids` **只增不删**，压缩后不会重新注入此前给过的历史修复——而压缩摘要极可能已把它从 live context 里抹掉。C4 与 C2 的差值，就是该缺口的代价。这条既是**研究假设（H-F）**，也是**待确认的产品缺陷**。

### 2.1 强制控制变量（**内容等价**，这是全课题成立的前提）

| 控制项 | 做法 |
| :--- | :--- |
| **事实集合等价** | MD 版必须承载与 tmem 版**完全相同的事实集合**（逐条对照清单核对）。否则比的是"谁记得多"，不是"载体谁更好" |
| **体量可比** | 两种载体的事实条目数一致；允许格式差异，不允许信息量差异 |
| **探针答案不可外得** | 答案不得出现在提示词、不得出现在初始代码（含已有的类名与常量）——上一轮的教训（报告 §3.6） |
| **逐字同题同约束** | 五臂使用逐字相同的任务提示与相同约束（例如"不要读代码"） |
| **工作区隔离** | 每臂独立工作区副本，禁止跨臂复用记忆库与工作区状态 |
| **同模型同预算** | 同一模型、同一 token 预算上限、同一超时 |

### 2.2 重复采样

模型非确定性是上一轮报告明确列出的局限。本课题要求**每臂 ≥ 3 次独立重复采样**（不同会话、独立工作区副本），所有比率类指标报**均值与 95% 置信区间**，并以**配对比较**（同场景、同重复序号）做显著性判断。

## 3. 量化指标（**必须机器可读、可复算**）

### 3.1 成本类（主指标）

| 指标 | 定义 | 采集方式 |
| :--- | :--- | :--- |
| **知识获取 token** | 为取得与任务相关的知识而消耗的 token = 注入块 token + 检索/读取工具的输出 token + 工具调用本身的开销 | transcript 中注入块按 tokenizer 计数；`tool/result` 的输出 token 计数 |
| **任务总 token** | 完成同一任务消耗的全部输入 + 输出 token | DSH transcript 的 usage 字段 |
| **上下文占用字节** | 注入或读取的知识文本字节数 | transcript 字节统计 |
| **知识密度** | 命中任务所需事实的 token ÷ 知识获取 token（越高越好） | 需人工标注"本任务所需事实集合" |
| **冗余率** | 1 − 知识密度 | 同上 |
| **折算成本** | token × provider 单价 | 单价取自当期官方价目表，记录来源与日期 |

> **H-A 的主判据 = 知识获取 token**（而不是总 token）：总 token 会被任务本身的思考长度淹没，噪声大；知识获取 token 直接测"载体效率"。

#### 3.1.0 已有锚点：Round 2 的 H6′ 首次给出可比数值（2026-11-22）

本课题开工前，独立 E2E 研究的披露式测量 **H6′** 已经用同一类"记忆专有事实 + 逐字同题 + 三臂"的设计，测到了**首个可复算的载体效率锚点**（详见 [`docs/dsh-independent-e2e-report.md`](./dsh-independent-e2e-report.md) §3.12）：

| 载体（获取方式） | 关键点命中率 | 知识获取 token | 读取次数 |
| :--- | :--- | :--- | :--- |
| **tmem 结构化记忆（回合级自动注入）** | **1.000** | **1 742** | 0 |
| tmem 结构化记忆（允许 agent 自行读取） | 1.000 | 27 076 | 6 |
| **散文式 MD 记忆（agent 自记笔记 + 允许读取）** | 1.000 | **77 710** | 14 |
| 无记忆（插件在、记忆库空） | 0.000（free 变体 0.333） | 12（free 58 757） | 0（free 11） |

据此得到本课题的**先验方向与量级**（**注意**：这是 n=1 的单次观测，**不是**本课题的门槛结论，只作为功效分析的输入）：

1. **注入式结构化载体相对"翻文件"的 token 比 ≈ 44.6×**（1 742 vs 77 710；字节口径 249 729 ÷ 5 462 = 45.7），相对"agent 自行读取结构化记忆"约 **15.5×**（1 742 vs 27 076）；
2. **零读取条件下**结构化注入臂才能拿到全部记忆专有事实（1.000），散文式 MD 臂只能拿到 1/3（0.333）——这正是"载体"差异第一次被分离出来的证据；
3. 因此本课题的**功效分析**应把 **CA-2（token 减少率）** 的预期效应量设在 **≥10×** 量级（远低于观测的 44.6×，以免过度承诺），而 **CA-1（命中率差）** 的预期效应量设在 **≥0.3**（观测 0.667）。

> **数值更正（2026-11-22）**：本节此前把"1 742 vs 77 710"的倍数写作 **≈22×**，经复核正确值为 **≈44.6×**（详见 [`docs/dsh-independent-e2e-report.md`](./dsh-independent-e2e-report.md) §3.12 的更正说明）。倍率变大只会让功效分析更宽松，因此下文的 n 估算**保留原按 22×（log 比值 3.09）计算的保守值不变**，作为下界使用。

> **方法学警告（必须写进本课题的执行检查表）**：Round 2 的对照臂曾两次失效，其中一次是**被测 agent 自行执行 `tmem init` 把插件装回对照臂**。本课题的"无记忆 / 散文式 MD"两臂必须**逐场断言**（工具清单 + 注入块 + 载体目录），不能靠配置意图。

#### 3.1.1 功效分析（基于 §3.1.0 的 n=1 观测，仅用于规划）

下面的 n 是**规划输入**，不是结论；效应量本身来自单次观测，必须在 pilot 阶段复核后才可采信。

**(a) 命中率类指标（CA-1：两比例单侧检验）**

以 H6′-1 的观测（p₁ = A_zero = 1.000，p₂ = B_zero = 0.333）代入标准两比例样本量公式（α = 0.05 单侧，power = 0.80，p̄ = 0.667）：

```
n ≈ ( z_α·√(2p̄(1-p̄)) + z_β·√(p₁q₁ + p₂q₂) )² / (p₁ − p₂)²
  = (1.645·0.667 + 0.842·0.471)² / 0.667² ≈ 5.0  →  每臂 6 次
```

| 情形 | 每臂重复次数 |
| :--- | :--- |
| 观测效应量成立（差 0.667） | **6** |
| 效应量减半（差 0.33） | 约 **22** |
| 效应量只剩 0.20 | 约 **60** |

> **风险提示**：命中率类指标对效应量极其敏感。若 pilot 显示真实差值只有 0.3 左右，本课题的每臂 3 次重复**不足以支撑显著性**，必须提高到每臂 ≥20 次或改为**配对设计**（同一题在多臂上重复，用配对检验的功效高得多）。因此 §2.2 的重复采样方案应优先采用**配对题集**。

**(b) token 类指标（CA-2：比值检验）**

知识获取 token 近似对数正态，令 σ_log 为每臂 log-token 的标准差，观测比值 44.6× ⇒ log 比值 = 3.80；为**保守**起见，下文的 n 估算仍按更小的 **22×（log 比值 3.09）** 作下界代入：

```
n ≈ ( z_α + z_β )² · σ_log² / (log 比值)²
```

| σ_log（每臂 log-token 波动） | 每臂重复次数 |
| :--- | :--- |
| 1.0（极稳） | 1（实际取 3） |
| 2.0 | 3 |
| **2.15** | **3（临界）** |
| 3.0 | 6 |
| 4.0 | 11 |

> 读法：**只要每臂 log-token 的标准差 ≤ 2.15（即重复间的比值波动不超过 e² ≈ 7.4 倍），每臂 3 次重复就够**；若波动更大，需 6 次以上。token 指标的功效明显优于命中率指标，**因此 CA-2 应作为主判据、CA-1 作为辅证**——这一点与 §3.1 的"主判据 = 知识获取 token"一致，并在本节得到了功效层面的独立支持。

**(c) 预注册门槛的效应量下限建议（写进 oracle）**

| 门槛 | 建议下限 | 依据 |
| :--- | :--- | :--- |
| CA-1（命中率差） | ≥ **0.30** | 与 H6′-1 预注册阈值一致；功效分析提示需 ≥20 次/臂，故**优先配对设计** |
| CA-2（token 减少率） | ≥ **10×** | 观测 44.6×（保守按 22× 下界），留 2 倍余量；10× 时 log 比值 = 2.30，每臂 n ≈ (6.18·σ²/5.29)，σ_log ≤ 2.15 时 n ≤ 6 |

### 3.2 效果类

| 指标 | 定义 |
| :--- | :--- |
| **首轮修复通过率** | 修复提交后**首次**验证即全绿的比例 |
| **回归引入率** | 修复引入新失败用例的比例 |
| **同签名复发率** | 跨会话同类错误签名再次出现的比例（**最有说服力的主效果指标**） |
| **修复采纳率** | 历史修复模式（异常类型 / 校验方式 / 根因处理）被新位置采用的比例 |
| **任务完成率** | 在预算内完成任务的比例 |
| **一次通过率（无需先验记忆）** | 首次尝试即写对目标文件的比例 |

### 3.3 结构化独有类

| 指标 | 定义 | 预期 |
| :--- | :--- | :--- |
| **L1 共变提示采纳精确率** | 被采纳的 L1 提示中命中真实共变对的比例 | tmem > 0；MD 臂恒为 0（散文表达不了"这两文件总是一起改"） |
| **错误签名 → 修复对命中率** | 按错误签名检索到正确历史修复的比例 | tmem 臂显著高 |
| **L0 验证路径命中率** | 注入的验证过路径仍然有效的比例 | tmem > MD |
| **guard 漂移降级率** | 路径漂移时正确降级为结构化不变式的比例 | tmem 独有 |
| **检索精确率 / 召回率** | `tmem lookup` 在中文自然语言下的表现 | 需 N1 修复后在位 |
| **跨语言召回缺口** | 中文提问 → 英文答案（命令 / 标识符）的命中率 | 已测得 **0**：中文问"运行单元测试用什么命令"0 命中，同一问题英文问 3 命中。二元组是词面匹配，中英之间无桥（缺陷 N8） |
| **措辞敏感度** | 同一事实、措辞不同（"单元测试" vs "测试失败基线"）时的命中率差 | 已测得：二元组覆盖 ≥15% 才命中，1 个二元组重合即漏 |
| **知识密度** | 命中任务所需事实的 token ÷ 检索返回 token | 与"载体效率"指标联动 |

### 3.4 压缩专项指标（**定性 + 定量**）

#### 3.4.1 定量指标

| 指标 | 定义 | 采集方式 |
| :--- | :--- | :--- |
| **记忆存活率** | 压缩前注入的事实集合中，压缩后仍被模型正确引用的比例 | 事实集合标注 + transcript 判定 |
| **重注入率** | 压缩后同一 trace 被**重新注入**的比例 | transcript 注入块 × `injected_trace_ids` |
| **重注入缺口** | 应重注入而未注入的次数（当前实现预期为 1−重注入率） | 同上 |
| **索引送达率** | 压缩归档产生了 `<tmem_compacted_index>` 通知的比例 | transcript 事件 |
| **索引展开率** | 收到通知后 agent 主动调用 `tmem_expand` 的比例 | `tool/call` 统计 |
| **索引命中率** | 展开取回的内容**确实含**所需事实的比例 | 事实集合标注 |
| **压缩后复发率** | 压缩后同一错误签名再次出现的比例 | 错误签名序列 |
| **压缩后修复采纳率** | 压缩后仍采纳历史修复模式的比例 | 语义判定 |
| **知识找回 token** | 压缩后为找回同一份知识**额外**消耗的 token | 压缩前后差值 |
| **压缩净成本** | （压缩 + 找回）总 token − 不压缩基线（C1）总 token | 同上 |
| **任务完成率（压缩 vs 不压缩）** | 各臂在预算内完成任务的比例 | — |
| **重复劳动时长** | 压缩后重新探索同一问题所耗的回合数 / token | transcript 回合切片 |

#### 3.4.2 定性分析：行为编码表

定量指标回答"多少"，**定性编码**回答"怎么坏的"。每条压缩后回合按下列编码归类（可两人独立编码并给出 Cohen's κ，κ < 0.6 则重写编码定义）：

| 编码 | 判定 | 特征（transcript 可观察） |
| :--- | :--- | :--- |
| **Q1 正确复用** | 压缩后直接沿用历史修复，无重复劳动 | 输出中引用根因/校验方式；改动集中在目标文件；同一错误签名未复现 |
| **Q2 部分复用** | 沿用部分结论，但另一部分重新探索 | 出现"我先看看/我猜"式重试；部分历史结论被正确引用 |
| **Q3 失忆重踩** | 完全重复了历史坑 | 同一错误签名再次出现，且修法与历史不同或相同但重新推导 |
| **Q4 索引未使用** | 收到 `<tmem_compacted_index>` 但未调用 `tmem_expand` | `tool/call` 中无 expand 调用 |
| **Q5 索引未送达** | 压缩归档未产生通知 | transcript 中无 `<tmem_compacted_index>` |
| **Q6 通知冗余** | 通知内容与当前任务无交集，徒增上下文 | 通知的 files / error_signatures 与当前任务无关 |
| **Q7 注入未重放** | 需要历史修复但未重新注入，模型被迫重新推导 | 压缩后同一 trace 缺席，且 agent 的行为像"第一次遇到" |

**定性产出**：每臂的编码分布 + 典型 transcript 片段 + **失败模式排序**（哪个编码占比最高、是否集中在特定臂）。定性结论必须与定量指标**交叉验证**：例如 Q7 占比高应与"重注入缺口 > 0"一致，否则说明编码定义或采集有误。

## 4. 场景剧本（承载载体差异的最小充分集）

沿用 `ledger-svc` fixture（**同一套真值 oracle**，便于与上一轮结果对照），新增三类场景：

| 场景 | 类型 | 设计意图 |
| :--- | :--- | :--- |
| **T1 跨位置同签名复发** | 主效果 | 在新位置复现历史错误签名 → 测"复发率"与"修复采纳率"，以及载体差异 |
| **T2 共变耦合改动** | 结构化独有 | 改动一个文件时，同步改动其强耦合伙伴 → 测 L1 采纳精确率（MD 载体无法提示） |
| **T3 知识检索问答** | 成本 | 回答"上次那个坑最后怎么修的、根因在哪一步" → 测知识获取 token 与命中率（答案不在提示词、不在初始代码） |

T3 的题目设计**必须满足**：答案不在任何提示词中、不在 fixture 初始代码中、只存在于先前会话的修复过程里（例如"改在哪一步、为什么不能抛裸 `ValueError`、`api.handle` 只捕获哪一类异常"）。

| 场景 | 类型 | 设计意图 |
| :--- | :--- | :--- |
| **T4 压缩后修复** | **压缩专项** | 在长会话中**于修复之前**强制触发一次上下文压缩，随后在**新位置**复现同类错误 → 测"记忆存活率 / 重注入缺口 / 索引展开率 / 压缩后复发率"，并产出 §3.4.2 的定性编码 |

**T4 的执行要求**：
- 必须**先注入历史修复 → 再触发压缩 → 再复现错误**，顺序不可颠倒（否则测不到"压缩把注入块抹掉"）；
- 压缩必须**真实发生**并在 transcript 中留下 `compaction_committed` 事件且 `shadowedSeqs` 非空，否则该次样本作废；
- 压缩点要**可复现**：用固定的会话长度/工具输出规模阈值触发，或直接调用 DSH 的压缩接口；
- 错误复现的位置必须是**新模块**（否则无法区分"记住"与"文件还在眼前"）。

## 7. 已知陷阱清单（来自上一轮研究的教训，必须写进执行检查表）

1. **不要用"结果指标"代替"机制指标"**：agent 自记笔记会遮蔽载体差异 → 必须做**内容等价**控制。
2. **无插件臂要真正无插件**：全局 CLI 必须移出 `PATH`，否则测的是"无自动注入"而非"无记忆"。
3. **探针不能有外得路径**：答案不得在提示词、不得在初始代码、不得在 agent 可随手读到的文件里。
4. **不要让基线臂被额外削弱**：像"不要读代码"这类约束会同时削弱记忆臂与基线臂，方向不定 → 要么去掉，要么三臂同施且在报告中显式说明其影响方向。
5. **合并会污染归因**：跨会话合并的 playbook 会把别的会话的文件并进来 → 归因统计用不合并的 episode。
6. **增量捕获会让"末次 capture 状态"失真**：末次跳过可能只是"本次增量无新内容" → 判定用会话级（该会话是否产出过 episode）。
7. **模型非确定性**：单次观测不可下结论 → ≥3 次重复 + 置信区间。
8. **配额是硬约束**：模型 API 可能中途 429 → 排期时预留重跑预算，并把"补跑清单"写进方案。
8b. **检索的跨语言边界必须在课题里显式测量**：tmem 的检索是确定性的**词面**匹配，中文提问命不中英文答案（缺陷 N8）。若不单独测量这一维度，会把"检索能力不足"误读成"载体没价值"。
9. **压缩是否真的发生要验证，不要假设**：必须在 transcript 中确认 `compaction_committed` 事件与非空 `shadowedSeqs`，否则该样本作废——否则会得出"压缩没影响记忆"的假结论。
10. **必须区分"模型忘了"与"tmem 没重注入"**：两者归因完全不同（前者是 harness 摘要能力问题，后者是插件缺陷）→ 用编码表的 Q3 与 Q7 分开计。
11. **不设 C3（压缩 + 无 tmem）就会高估 tmem**：harness 原生摘要可能已保住大部分关键信息 → C3 是强制对照臂。
12. **压缩会顺带 prune 工具输出**，原始证据可能被裁剪 → 必须确认 `.tmem/raw/` 归档完整，否则取证失败、样本作废。
13. **压缩时点会与任务阶段耦合**：若总是在同一阶段压缩，效应会与阶段效应混淆 → 压缩点须随机化或至少轮换位置。

**关键设计决策（Phase-1）**：

1. **单一事实源、双载体**：散文载体由 tmem 载体的 episode 记录机械渲染而来（`render_prose_carrier.py`），因此"事实集合等价"由构造保证、并可被 grep 独立复核——这是 CA-5 前置门能自动判定的前提。
2. **A2 用机制消融而不是配置意图**：A2 臂挂载一份**打过补丁的 tmem 包副本**（PATH 上的 `tmem` 指向它），补丁只关掉"自动注入"这一行（`TMEM_ABLATE_NO_INJECT=1`），捕获、遥测、检索工具全部不变；补丁以 diff 形式留档。
3. **对照臂真正无 tmem**：对照臂使用**独立的 DSH_HOME**（home patch 无 tmem 条目），且 PATH 前置 `blockbin` 把全局 `tmem` CLI 彻底挡住（协议陷阱 #2）。
4. **载体混淆自动作废**：评分脚本机械判定——对照臂一旦出现 `tmem_search`/`tmem_expand` 调用或 `<tmem_speculative_memory>` 注入块，该样本直接作废并留痕，不允许人工挑选。
5. **提示词载体中立**：AGENTS.md 在所有臂都被改写成**同一段载体中立指引**（安装器会给 tmem 臂追加一段 tmem 专属协议，若保留会给 A 臂额外优势）。提示词措辞也改为"本项目可用的项目记忆"，五臂逐字相同。
